## 1. 背景与目标

父工作项若只能看到计数、无法在详情内管理子项，层级价值半残。目标：在详情中提供完整子项面板——列表、快速新建、关联已有、打开子项；操作受层级规则约束。

## 2. 范围 / 非目标

**范围**

- 详情「关联」（或等价页签）内子项面板：列出直接子项（标识、标题、状态/优先级要点）。
- 快速新建子项（标题 + 可选类型）；关联已有工作项为子项。
- 点击子项进入其子详情；空状态有明确文案与 CTA。
- 可选 P1：拖拽/接口重排序（已有 `reorder-sub-issues` 则纳入验收）。
- 所有写入遵守类型层级 SRS。

**非目标**

- 不在列表行内展开无限树（树视图另议）。
- 不在本 SRS 做跨项目子项。

## 3. 现状对照

| 已有 | 缺口 |
|------|------|
| `RelationSubIssuesCard`、详情关联页快速新建/关联 | 需用 GWT 钉死空状态、权限、层级失败提示、计数同步 |
| `POST .../reorder-sub-issues`、`children` API | 前端排序是否暴露为 P1 |

## 4. 功能需求

| ID | 需求 |
|----|------|
| FR-01 | 展示直接子项列表与空状态 |
| FR-02 | 快速新建子项 |
| FR-03 | 将已有工作项设为子项 |
| FR-04 | 层级/权限失败时可见错误，数据不变 |
| FR-05 | 子项数量与面板一致（详情头或页签计数） |
| FR-06 | （P1）重排序子项并持久化 |

## 5. 验收场景（Given / When / Then）

### AC-01.1 空状态
Given 工作项无子项，用户有编辑权限  
When 打开详情关联/子项区域  
Then 看到空状态说明  
And 看到可发起「新建」或「添加已有」的入口

### AC-02.1 快速新建子项
Given 父项 depth < 5，存在合法子类型  
When 在面板输入标题并确认快速新建  
Then 列表出现该子项  
And 子项 `parent_id` 为当前工作项

### AC-03.1 添加已有为子项
Given 同项目另一无父工作项可作为合法子类型  
When 用户从选择器将其添加为子项  
Then 面板列出该项  
And 其 `parent_id` 已更新

### AC-04.1 深度非法
Given 父项 depth = 5  
When 尝试快速新建子项  
Then 操作失败并提示深度限制  
And 面板子项数量不变

### AC-05.1 计数一致
Given 面板显示 2 个子项  
When 用户查看详情上的子项计数（页签或字段）  
Then 计数为 2

### AC-06.1 重排序（P1）
Given 面板有至少两个子项且 UI 提供排序  
When 调整顺序并保存  
Then 刷新后顺序保持

## 7. 接口与数据约束要点

- 创建子项：`POST /issues/` + `parent_id`。
- 改父子：更新 issue `parent_id`。
- 列表：详情 payload 的 `sub_issues` 或 `GET /issues/:id/children`。
- 排序：`POST /issues/:issueId/reorder-sub-issues`（P1）。

## 8. 风险与开放问题

- 页签命名（关联 vs 子项）以现网 UI 为准；GWT 用「子项面板所在页签」表述。
