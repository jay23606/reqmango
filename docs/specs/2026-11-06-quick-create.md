## 1. 背景与目标

完整创建表单路径成本高。目标：在**工作项列表与看板**上用最少字段创建顶层工作项，创建后仍留在当前视图，支持连续录入。

## 2. 范围 / 非目标

**范围**

- 列表顶部：标题必填；类型、优先级可选（有项目默认则预填）；Enter 或确认创建。
- 看板：按状态分列时，列内「+」展开同行内创建；新项落入该列对应 `state_id`。
- 复用现有 `POST /issues/`，不新增创建 API。
- 无 `issue:create`（或项目等价权限）时不展示入口。
- 成功：当前视图出现新项，输入框清空并保持可继续输入；失败：toast / i18n，保留已输入标题。

**非目标**

- 不替代 `IssueCreate` 完整表单（描述、多选人、自定义字段等）。
- 首版不做树 / 日历 / 甘特上的快速新建。
- 不重做详情里子工作项快速创建（`RelationSubIssuesCard`）；交互可对齐但不在本 SRS 改行为。

## 3. 现状对照

| 已有 | 缺口 |
|------|------|
| `IssueCreate` 完整创建；`POST /issues/` | 列表 / 看板无顶层行内创建 |
| 详情关联页子项快速创建 | — |

## 4. 功能需求

| ID | 需求 |
|----|------|
| FR-01 | 列表顶部快速新建（标题 + Enter / 确认） |
| FR-02 | 看板列内快速新建（带目标状态） |
| FR-03 | 默认值：类型 / 优先级 / 看板状态来自上下文 |
| FR-04 | 无权限隐藏入口；失败可重试且不丢标题 |
| FR-05 | 创建后当前视图可见新项，焦点回到输入框便于连续创建 |
| FR-06 | 若目标类型存在必填自定义字段且请求未提供：后端 4xx 列出字段名；前端提示并可引导完整表单（与必填 SRS 一致） |

## 5. 验收场景（Given / When / Then）

### AC-01.1 列表创建成功
Given 成员在 Demo 项目工作项列表且有创建权限，项目有默认工作项类型  
When 在列表顶部输入标题「登录偶发失败」并按 Enter  
Then 列表出现标题为「登录偶发失败」的工作项  
And 未导航离开列表页  
And 输入框已清空且仍可输入

### AC-01.2 空标题拒绝
Given 成员在列表快速新建输入框中  
When 标题为空时按 Enter  
Then 不调用创建成功路径（无新工作项）  
And 用户看到校验提示

### AC-02.1 看板列内创建带状态
Given 成员在看板视图，列按状态分组，其中一列对应状态「进行中」  
When 在该列点击「+」，输入标题「修支付回调」并确认  
Then 新工作项出现在「进行中」列  
And 该工作项的状态为「进行中」

### AC-04.1 无权限无入口
Given 用户对项目无创建权限  
When 打开该项目列表或看板  
Then 不展示快速新建入口

### AC-06.1 必填自定义字段拦截
Given 当前所选类型将自定义字段「复现步骤」标为必填  
When 快速新建仅提交标题、不传该字段  
Then API 返回 4xx，信息中含「复现步骤」  
And 数据库无对应新工作项  
And 前端保留标题并提示失败原因

## 7. 接口与数据约束要点

- `POST /api/v1/issues/?project_id=&workspace_id=`，body 至少含 `name`；看板路径带对应 `state_id`。
- 权限与现有创建一致；错误走现有 error envelope（`error_code` / `message`）。
- 不新增专用 quick-create 端点。

## 8. 风险与开放问题

- 看板若非按状态分组，列内默认状态规则须在 Design 写死（建议：仅状态分组启用列内「+」，否则仅用列表顶部入口）。
