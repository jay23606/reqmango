## 1. 背景与目标

附件是工作项证据链的一部分。目标：在详情中稳定地上传、列表、下载、删除；大小与权限有硬限制；本地文件系统存储（与现架构一致）。

## 2. 范围 / 非目标

**范围**

- 详情附件页签：上传、列表、下载、删除、预览入口（若已有预览组件则保持）。
- 单文件上限 **10MB**（与现 handler 一致）；超限 413 或等价 4xx，文案含大小限制。
- 权限：`issue:edit`（或等价）可上传/删除；有 issue 读权限可列表/下载。
- 存储：服务器本地 `uploads` 目录；文件名存储用服务端 ID，客户端原名仅作展示名。
- `attachment_count`（或页签计数）与列表一致。

**非目标**

- 对象存储 / CDN / 病毒扫描。
- 附件作为自定义字段类型。
- 批量打包下载。

## 3. 现状对照

| 已有 | 缺口 |
|------|------|
| `AttachmentService` / handler；10MB；`AttachmentManager.vue`；list/upload/delete/download API | 需用 GWT 钉死权限、超限、计数、删除后不可下载 |

## 4. 功能需求

| ID | 需求 |
|----|------|
| FR-01 | 上传并出现在列表 |
| FR-02 | 下载内容与上传一致（或可读的二进制） |
| FR-03 | 删除后列表与下载均不可用 |
| FR-04 | 超过 10MB 拒绝 |
| FR-05 | 无编辑权不可上传/删除；有读权可下载 |
| FR-06 | 计数与列表一致 |

## 5. 验收场景（Given / When / Then）

### AC-01.1 上传成功
Given 用户有 issue:edit，打开工作项附件页签  
When 上传一个小于 10MB 的文件 `note.txt`  
Then 列表出现展示名为 `note.txt` 的项  
And 刷新后仍在

### AC-02.1 下载
Given 上一步附件已存在  
When 用户下载该附件  
Then 获得可打开的文件内容与上传一致（文本场景下字节/文本相同）

### AC-03.1 删除
Given 附件存在  
When 用户删除它  
Then 列表不再显示  
And 再请求下载返回 404 或等价失败

### AC-04.1 超限
Given 用户选择大于 10MB 的文件  
When 尝试上传  
Then 上传失败，提示含大小限制  
And 列表不新增该项

### AC-05.1 只读不能上传
Given 用户仅有读权限  
When 打开附件页签  
Then 无上传/删除控件（或操作返回 403）  
And 仍可下载已有附件（若业务允许只读下载；若项目对只读禁止下载，Design 写死并改本条为「下载亦 403」——**默认允许只读下载**）

### AC-06.1 计数
Given 列表有 2 个附件  
When 查看详情页签上的附件计数  
Then 显示 2

## 7. 接口与数据约束要点

- `GET/POST /api/v1/issues/:issueId/attachments`
- `GET .../attachments/:id`、`.../download`、`DELETE .../:id`
- 上限：10MB（`MaxBytesReader`）；存储路径不含用户可控目录段。

## 8. 风险与开放问题

- 多实例部署时本地盘不共享——生产须单实例或共享卷；属部署约束，不在本 SRS 做对象存储。
