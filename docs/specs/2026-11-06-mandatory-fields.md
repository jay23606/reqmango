## 1. 背景与目标

自定义字段可标 `is_required`，但若只在部分写入路径生效，字段约束不可信。目标：凡标记必填的自定义字段，在创建、更新、类型转换、正式导入时统一强制；前端有明确标记与错误提示。

## 2. 范围 / 非目标

**范围**

- 类型绑定上的必填标记对后续写入立即生效。
- **创建、更新、转换类型（目标类型新增必填）、导入（非 dry_run）** 使用同一校验规则。
- 缺字段：HTTP 4xx，信息含字段显示名列表；不写库（创建）或不提交无效更新。
- 前端创建页与详情编辑：必填 `*`；失败可理解（i18n）。
- 空字符串、`null`、缺失键视为未填；布尔 `false`、数字 `0` 视为已填。

**非目标**

- 条件显隐（见条件显隐 SRS）；本 SRS 假定字段可见时的规则。
- 不改系统标准字段（如 `name`）既有必填。
- 不做跨项目字段库重构。

## 3. 现状对照

| 已有 | 缺口 |
|------|------|
| `issue_type_fields.is_required`；创建时 `validateMandatoryCustomFields` | 更新路径未统一调用 |
| `IssueCreate.vue` 前端必填与提交前检查 | 详情内联编辑 / 转换类型 / 导入是否全覆盖需用本 SRS 验收钉死 |

## 4. 功能需求

| ID | 需求 |
|----|------|
| FR-01 | 配置：类型上标记/取消必填，对后续写入立即生效 |
| FR-02 | 创建强制校验（含 API 直调、快速新建） |
| FR-03 | 更新强制校验；清空必填视为失败 |
| FR-04 | 转换类型、正式导入与创建同一规则 |
| FR-05 | 前端必填展示与失败提示（zh / en） |

## 5. 验收场景（Given / When / Then）

### AC-02.1 创建缺少必填
Given 类型 Bug 将自定义字段「复现步骤」标为必填  
When 客户端创建该类型且不传该字段（或传空字符串）  
Then 返回 4xx，正文含「复现步骤」  
And 库中无新工作项

### AC-02.2 创建含必填成功
Given 同上类型  
When 创建时提供非空「复现步骤」  
Then 创建成功，工作项可读取到该字段值

### AC-03.1 更新清空必填失败
Given 已存在 Bug 工作项且「复现步骤」有值  
When 更新请求将该字段设为清空（空字符串或显式清除）  
Then 返回 4xx  
And 库中该字段仍为原值

### AC-04.1 转换类型补齐必填
Given 工作项从无该必填的类型转为 Bug（「复现步骤」必填）且未提供该字段  
When 调用转换类型接口  
Then 返回 4xx，提示缺少「复现步骤」  
And 工作项类型未改变

### AC-04.2 导入非 dry_run
Given CSV/JSON 正式导入（非 dry_run）某行类型为 Bug 且缺「复现步骤」  
When 执行导入  
Then 该行失败或整批按现有导入错误语义失败，且不留下缺必填的成功行  
And 错误信息可关联到该字段

### AC-05.1 前端创建页标记
Given 用户打开创建页并选择 Bug 类型  
When 表单渲染自定义字段  
Then 「复现步骤」显示必填标记  
And 不填提交时前端阻止或展示与后端一致的缺失提示

## 7. 接口与数据约束要点

- 数据：`issue_type_fields.is_required`（及等价绑定）为权威；与字段定义上的 `is_required` 若并存，以类型绑定为准（与当前 create 校验一致）。
- 写入：`POST /issues/`、更新 issue、convert-type、import 非 dry_run 均须校验。
- 错误：4xx + 可读字段名；快速新建适用同一规则。

## 8. 风险与开放问题

- 历史数据已缺必填时，「仅更新其他字段」是否触发全量必填检查：本 SRS 约定 **更新若触及自定义字段映射或显式提交 cf 值则校验；纯改标题等不强制补历史洞**——若实现选择「任何更新都全量校验」，须在 Design 写明并改本条。
