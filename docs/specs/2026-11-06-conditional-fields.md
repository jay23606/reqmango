## 1. 背景与目标

部分自定义字段只在特定类型/状态等上下文有意义。目标：按规则隐藏字段；隐藏中的必填不拦提交；创建/详情 UI 随上下文变化。

## 2. 范围 / 非目标

**范围**

- 规则维度与现实现一致：`type` / `state` / `priority` / `assignee` / `label`；条件命中则 **隐藏** 目标字段。
- 管理员可 CRUD 规则（工作空间边界与现 API 一致）。
- 创建页、详情编辑应用显隐；提供评估结果（可见字段 ID 列表）供前端使用。
- **必填**：仅对当前可见的必填字段强制；隐藏中的必填不拦提交。
- 无规则字段默认可见；禁用/删除规则后恢复可见。

**非目标**

- 「自定义字段 A 的值决定字段 B 显隐」——不在本 SRS（另开后续规格）。
- 复杂 AND/OR 表达式树；首版保持现有单规则 + priority 排序语义。

## 4. 功能需求

| ID | 需求 |
|----|------|
| FR-01 | 规则配置 CRUD |
| FR-02 | 给定上下文评估可见字段集 |
| FR-03 | 创建 / 编辑 UI 应用显隐 |
| FR-04 | 写入时隐藏字段不参与必填；客户端不得靠藏字段绕过仍可见的必填 |
| FR-05 | 关闭或删除规则后字段默认可见 |

## 5. 验收场景（Given / When / Then）

### AC-01.1 创建隐藏规则
Given 项目管理员在工作空间中  
When 创建规则：状态 = 「完成」时隐藏字段「预估工时」，并启用  
Then 规则可被列表接口读回且 `is_enabled` 为 true

### AC-02.1 评估隐藏
Given 上述规则已启用  
When 以状态「完成」调用显隐评估（或等价上下文）  
Then 返回的可见集合不包含「预估工时」的 field id

### AC-03.1 UI 隐藏
Given 用户编辑一工作项且状态为「完成」，规则同上  
When 打开自定义字段编辑区  
Then 不展示「预估工时」输入控件

### AC-04.1 隐藏中的必填不拦提交
Given 「预估工时」标为必填，且规则在状态「完成」时隐藏它  
When 将工作项更新为「完成」且不传「预估工时」  
Then 更新成功

### AC-04.2 可见必填仍强制
Given 状态为「进行中」时「预估工时」可见且必填  
When 更新时清空或不传该字段  
Then 返回 4xx（符合必填 SRS）

### AC-05.1 删除规则恢复可见
Given 规则被删除或 `is_enabled=false`  
When 用户在状态「完成」下打开编辑  
Then 「预估工时」重新可见

## 7. 接口与数据约束要点

- CRUD：现有 `/projects/:projectId/conditional-fields`（以实现为准）。
- 评估：`EvaluateFieldVisibility(workspaceID, issueTypeID, stateID, priority, assigneeIDs, labelIDs)`；条件命中 → 隐藏。
- 写入路径在校验必填前须先得到「当前可见字段集」。

## 8. 风险与开放问题

- 前端切换状态时的防抖与评估频率在 Design 中定。
- 若产品后续要「显示条件」而非「隐藏条件」，属破坏性语义变更，需新 SRS。
