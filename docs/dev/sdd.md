# Spec-Driven Development（SDD）约定

> 新功能先冻结需求与验收，再写 design / plan，再改代码。  
> 规格是验收的唯一对照，不是实现日记。

**状态：** 已生效（2026-11-06）  
**关联：** [ROADMAP.md](../../ROADMAP.md) · [docs/specs/](../specs/)

---

## 1. 目的

- 把「做什么 / 不做什么 / 怎样算完成」写清楚，再开工。
- 验收以 **Given / When / Then** 场景为准；清单表只做勾选索引。
- 叙述用中文；路由、字段、组件、错误码等标识符保持英文。

---

## 2. 文档类型

| 类型 | 位置 | 写什么 | 何时写 |
|------|------|--------|--------|
| **SRS（需求规格）** | `docs/specs/YYYY-MM-DD-<slug>.md` | 背景、范围、非目标、现状对照、FR、GWT 验收、接口/数据约束要点 | 动手前 |
| **Design** | `docs/superpowers/specs/` | 方案、边界、关键数据结构 | SRS 状态为「已冻结」之后 |
| **Plan** | `docs/superpowers/plans/` | 分任务实现步骤（TDD、文件路径） | Design 通过后 |
| **Acceptance 跑表** | `docs/dev/acceptance/` | 手测 / 自动化勾选结果 | 实现后对照 SRS |

索引见 [docs/specs/README.md](../specs/README.md)。

---

## 3. SRS 必备章节

1. **元信息**：状态（草稿 / 已冻结 / 已实现 / 已验收）、关联 ROADMAP / Issue  
2. **背景与目标**  
3. **范围 / 非目标**  
4. **现状对照**（已有 / 缺口）——以代码为准，不抄过时计划  
5. **功能需求 FR-xx**  
6. **验收场景**：每条 P0/P1 必须是完整 `Given / When / Then`（可加 `And`）  
7. **验收清单**：勾选索引，每行指回一条 GWT  
8. **接口与数据约束要点**（路径、关键字段、错误语义；不写逐步改哪些文件）  
9. **风险与开放问题**（无则写「无」）

深度约定（本仓库默认）：需求与验收 + 现状对照 + 接口/数据约束要点；**不**把逐步实现计划写进 SRS。

---

## 4. 验收写法（强制）

### 4.1 Given / When / Then

```text
### AC-01.1 <短标题>
Given <前置状态，含角色/项目/数据>
When <一个用户或系统动作>
Then <可观察结果>
And <可选的补充结果>
```

禁止只写「功能可用」「显示正确」「行为符合预期」等无场景句子。

### 4.2 清单表（索引）

| AC-ID | 场景摘要（对应 GWT 标题） | 优先级 | 结果 |
|-------|---------------------------|--------|------|
| AC-01.1 | … | P0 | |

- **P0** 全过才算该 SRS 完成。  
- **P1** 可进下一迭代，但须在 SRS 标明。  
- 「结果」列留给验收填写（PASS / FAIL / 跳过+原因）。

### 4.3 与实现的关系

- 快速新建等路径**不得**绕过已冻结的必填等约束；跨 SRS 依赖在正文写明。  
- PR 描述须引用相关 `FR-xx` / `AC-xx.y`。

---

## 5. 门禁

1. 无 SRS，或 SRS 状态不是 **已冻结**，不进入 Design。  
2. Design / Plan 论证必须能指回 SRS 的 FR 与 AC。  
3. 合入后把 `docs/dev/acceptance/` 跑表链回对应 SRS；全 P0 PASS 后可将 SRS 标为 **已验收**。

---

## 6. 命名与语言

| 项 | 约定 |
|----|------|
| 文件名 | `YYYY-MM-DD-<english-slug>.md` |
| 标题 | 中文产品名 + 「需求规格说明书（SRS）」 |
| 正文 | 中文 |
| 标识符 | 英文（API path、JSON field、组件名、事件名） |

---

## 7. 修订

修订 SRS 时更新文首版本表；已冻结后的行为变更须 bump 版本并注明对哪些 AC 的影响。过时实现细节以代码与新 SRS 为准，旧 `plane-gap` 计划仅作历史参考。
